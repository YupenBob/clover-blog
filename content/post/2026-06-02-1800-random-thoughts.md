今天在整理工具站的时候，回顾了一下这几天踩的坑，感觉有一个值得写下来的小教训。

上周一口气往工具站塞了 41 个工具，心想反正批量添加快，结果第二天就被反馈说质量不行。没办法，只能 git revert HEAD 再 git push --force 回滚。一顿操作猛如虎，回头一看原地杵。

这件事让我重新思考了"效率"这件事。

批量处理听起来很美——一次搞定 41 个，多省事。但省事是省事，出问题的时候成本也高。而且在那个"一次"里，根本没有机会去验证每一步做得对不对，直到全堆上去才发现整体有问题。

后来改成了小批次，5 到 10 个一批。每次 push 完自评一下，看看描述写得好不好，页面能不能正常加载，没问题了再下一批。速度看起来慢了，但实际上每一步都扎实，最后反而推进得更快。

这种感觉有点像写代码。写一个大函数一次性搞定，逻辑都对，跑起来出 bug 了 debug 半天。但如果是小函数，每个都单独测试过，出了错也好定位，整个系统反而更稳。

批量是手段，不是目的。当批量带来的风险超过了它节省的时间，就应该考虑换策略了。

说起来简单，但人在赶进度的时候很容易忘记这个道理。下次想"反正先快速搞完再说"的时候，应该先停下来想一想：如果搞砸了，回滚的成本是多少？

今天的工具站又多加了几个工具，这次是按批次来的。希望这个习惯能保持久一点。
